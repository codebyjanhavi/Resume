# SkillSight AI — Machine Learning and Analysis Methodology

SkillSight AI combines one trained classifier with text-similarity, rule-based skill matching, regex-based skill extraction, and deterministic learning recommendations. Not every component is a machine-learning model.

## 1. Job-role classifier

- **Goal:** Predict one of 15 technical job-role categories from resume text.
- **Deployed estimator:** `CalibratedClassifierCV` wrapping `LinearSVC`. Calibration enables class-probability estimates used to return a confidence and alternative roles.
- **Text features:** `TfidfVectorizer` with up to 5,000 features, unigrams and bigrams, English stop words removed, sublinear term frequency, and `min_df=2`.
- **Training split:** Stratified 80/20 train/test split using random seed `42`. The vectorizer is fitted on the training text and then applied to test text.
- **Candidate comparison:** Five-fold stratified cross-validation compares Logistic Regression and LinearSVC using macro-F1. The script fits both candidates and evaluates them, but saves the calibrated LinearSVC and its vectorizer for inference.
- **Saved files:** `backend/artifacts/job_role_classifier.joblib`, `tfidf_vectorizer.joblib`, and `metrics.json`.
- **Runtime:** `backend/app/ml/predictor.py` loads these artifacts; `backend/scripts/train_models.py` trains and writes them.

The supplied synthetic benchmark currently reports 100% held-out accuracy. Since the test set is synthetically generated from the same generator, that score is not evidence of equivalent performance on real-world resumes.

## 2. Resume-to-job text similarity

`MatchingEngine.calculate_text_similarity` creates TF-IDF vectors for the resume and target description, then calculates cosine similarity. It returns a percentage from 0 to 100. The implementation fits the vectorizer to the two texts being compared; this is a lexical text-overlap signal and should not be interpreted as a hiring score or a separately trained semantic model.

## 3. Skill compatibility

The compatibility engine compares the user's confirmed skills with the target role's mandatory and preferred requirements. It is deterministic and rule-based:

- Mandatory requirements use the configured requirement weight (typically `1.0`).
- Preferred requirements use the configured requirement weight (typically `0.6`).
- Mandatory coverage is the matched mandatory weight divided by total mandatory weight.
- Overall coverage combines matched mandatory and preferred weights divided by their combined total weights.

The result categorizes matched skills, missing mandatory skills, missing preferred skills, and additional candidate skills.

## 4. Skill extraction

`backend/app/services/skill_extractor.py` contains a curated in-code skill taxonomy and aliases. It builds case-insensitive regular expressions with token-boundary checks, sorts aliases so longer phrases are checked first, and maps recognized aliases to canonical skill names and categories. For example, `k8s` is normalized to `Kubernetes`. This is a rules-based NLP technique, not a statistical model.

## 5. Recommendations and resume suggestions

The matching engine builds roadmap items from missing requirements:

- Missing mandatory skills receive high priority, a beginner stage, and a suggested project/resource.
- Missing preferred skills receive medium priority, an intermediate stage, and a suggested project/resource.

Curated resources and project examples are maintained in code, with generic fallback suggestions for skills that do not have a specific entry. Resume-improvement advice is heuristic and checks resume text and detected sections; it is not generated by an AI language model.

## 6. Dataset and reproducibility

The role classifier is trained from 5,250 fictional resume profiles (350 per role) included under `backend/data/synthetic/`. The dataset-generation program uses seed `42`. The training pipeline also uses fixed random seeds for the split and validation. See [dataset.md](./dataset.md) for file names and columns.

Training or regenerating data is optional for running the app because the CSV files and trained artifacts are included.

## 7. Limits and interpretation

- Synthetic examples may not represent the variety, formatting, and skill language of real resumes.
- A predicted role and its confidence are model outputs, not verified qualifications.
- TF-IDF cosine similarity measures word/phrase overlap, not deep semantic understanding.
- Coverage depends on the target role's configured requirements and skills confirmed by the user.
- These features support career exploration and self-assessment only; they should not make automated employment decisions.
